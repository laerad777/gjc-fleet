## Public contract gaps (U1–U5 preserved)

- **U1 — read-only original-request lookup:** Coordinator supports full identical request/key replay, but no separate actor/namespace/key/payload-digest lookup for an unknown create/turn response. `read_turn` needs the returned Coordinator turn ID. SDK CLI `session.create`/`session.lookup` is an existing public pair for SDK-created sessions only; its lifecycle facade hashes actor namespace/id/request key/operation, whereas Coordinator forwards a `remote_`-prefixed mapped key directly. Passing either Coordinator's caller key or a source-computed mapped key to that CLI hashes it again under another actor; identical cwd alone also does not establish target equality. This module holds the original uncertainty rather than switching actors/keys or reading private launch context. A minimal future public Coordinator lookup should accept the original tool/key/request identity and perform its existing mapping internally, without creating another execution.

This module does not transfer unresolved ownership, expire slots or launch a successor. - **U3 — genuine approval and ordinary questions:** Workflow uses public `list_questions`/`submit_question_answer` with exact session/turn/question/schema/binding; accepted is not consumed. - **U4 — exact input/dependency separation:** Exact task-owned worktrees use the existing cwd selector, avoiding native HEAD/implicit dependency behavior. `input preview/authorize/import` and bound node preparation support explicit binary/untracked/deleted/mode snapshots plus an integrity-checked exact current commit/tree/blob closure, no ancestors or unrelated objects.
